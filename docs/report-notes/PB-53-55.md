# PB-53 – PB-55 Usability fixes: onboarding wizard, search and filters, dark mode

Sprint 3 · stories · 8 + 5 + 3 points · traces to the Sprint 3 usability test, NFR usability and
accessibility, FR1 · GitHub issues #63, #64, #65

Built as one item: all three came out of the same usability test and touch the same pages. The
wizard (PB-53) is new pages that need PB-54's return links and PB-55's dark-mode check, and PB-55's
four-theme accessibility run must cover the new wizard and filter pages. See `docs/decisions.md`,
19 Nov 2026.

## What was built

### PB-53 Continuous onboarding flow

- **One wizard instead of three separate pages.** Borrowers go through
  *Your details → Address → Documents → Review and submit*; investors have *Risk acknowledgement*
  before the review. The steps are shown across the top with the `OnboardingStepper` (new `nav`
  variant: steps already reached are links, the step on screen is marked `aria-current="step"`).
- **Saves as you go.** Every step saves on *Continue* and moves to the next step, never out of
  the wizard (the old acknowledgement page used to send investors back to the portal).
  `/borrower/onboarding` and `/investor/onboarding` always resume at the first step that isn't
  done, so leaving and coming back picks up where the user stopped. A step after that one can't be
  opened (or saved) yet: the server redirects to the current step.
- **Earlier steps stay editable until verification**, with the existing lock: once verified, every
  step is read-only (*Next* instead of *Continue*) and every save is refused with 403.
- **Structured Maldivian address.** House or building name, road (magu), atoll and island
  (dropdowns, the island list filtered by the chosen atoll) and a 5-digit postcode. The list of
  21 atolls (the 20 administrative atolls and Malé City) and 188 inhabited islands is seeded by a
  migration from `web/database/data/maldives_islands.php`. **Source:** Wikipedia, "List of islands
  of the Maldives", revision 1385883966, fetched 19 Nov 2026
  (<https://en.wikipedia.org/w/index.php?title=List_of_islands_of_the_Maldives&oldid=1385883966>),
  with the island lists of the ten atolls covered by the article's census table taken from that
  table (Maldives Bureau of Statistics, Census 2022, Table P3,
  <https://census.gov.mv/2022/wp-content/uploads/2023/03/Table-P3.pdf>). Malé, Hulhumalé and
  Villimalé are listed under Malé City; the Bureau's total is 187 inhabited islands, the list has
  188 because Addu's Maradhoo-Feydhoo, Hulhudhoo and Meedhoo are kept as the names people write in
  addresses.
- **Fixed document slots.** Individual borrower: national ID card, proof of address. SME borrower:
  national ID card, business registration certificate, proof of business address, financial
  statement. Investor: national ID card, proof of address. Each slot says exactly what to upload;
  a filled slot shows the file with *View* and *Replace*. There is no "choose a document type"
  form any more, and the server refuses any type that isn't one of the user's slots. Uploads keep
  PB-09's protection: real-type checks, 5 MB limit, random names on the private disk, AES-256
  encryption with `APP_KEY`, and the owner-or-admin download route.
- **Review and submit.** The last step shows everything the administrator will check, with links
  back to each step, and a *Submit for verification* button. The admin queue now lists an account
  only once it is complete *and* submitted. After a rejection the user fixes their details and
  submits again (before, any edit put the account straight back in the queue).
- **Risk acknowledgement as the investor's last step**, and its sidebar item is gone. Profile and
  Documents became one *Account setup* item; the old URLs redirect to the matching step. The
  warning "Returns are not guaranteed." became "Your returns could be lower than expected, or you
  could receive nothing." (same meaning, so the version stays `2026-11-v1` and nobody accepts
  again), because Shariah-only investors now see this step in Shariah mode.
- **Existing data migrated without loss.** Each old single-line address is copied to
  `address_legacy`, split into the new fields as a best guess (`LegacyAddress`), and the profile is
  flagged (`address_needs_review`) so the address doesn't count until the user has checked it; the
  address step shows the original text above the fields. Existing documents are mapped into their
  slots: the newest upload of each type becomes the current one and older ones are marked replaced
  (rows and files kept). Accounts that were already in the queue are marked submitted. Every
  migration rolls back to exactly the data that was there before.

### PB-54 Search, filters and return navigation

- **One shared search-and-filter bar, `ListFilters`.** Search as you type (the reload waits 300 ms
  after the last key), dropdown filters, a *Clear filters* button and a result count announced to
  screen readers. Filtering happens on the server through Inertia partial reloads (only the list
  props are fetched), and the values live in the URL, so a filtered list can be bookmarked,
  reloaded or returned to.
- **Used on every existing list:**

  | List | Search | Filters |
  |---|---|---|
  | Admin verification queue | name, email | role, borrower type |
  | Admin campaigns (both tabs; the open tab is in the URL too) | title, borrower name | contract, purpose |
  | Borrower requests | title | status, contract |
  | Investor marketplace | title, business name (never an individual's name) | contract, purpose |

- **A rule for future lists**: the design system README ("Lists, search and return navigation")
  and the project's CLAUDE.md say every list must use this bar.
- **Return navigation.** Links between pages carry `?return_to=<the page they came from>`. Back
  links, the new breadcrumbs in the top bar and the redirect after an admin decision go there, so
  *campaign review → borrower's verification record → Back to the campaign review* works, and the
  review still knows its way back to the filtered campaign list. Only internal paths that match one
  of the app's pages are accepted; anything else (another site, `//host`, `/\host`,
  `javascript:`, encoded tricks) falls back to the page's normal parent.

### PB-55 Dark / light mode toggle

- **A theme toggle** (light, dark, system) at the bottom of the sidebar and in the mobile menu. In
  the collapsed sidebar it becomes three stacked icons with tooltips.
- **Saved per user**, defaulting to *system* (the device's setting).
- **No flash of the wrong theme.** The server writes the saved theme on `<html>` in the very first
  HTML. For *system* it can't know the device setting, so a three-line script in `<head>` sets it
  from `prefers-color-scheme` before the stylesheet applies (checked by the screenshot run on a
  device set to dark).
- **All four palettes** (conventional and Shariah, each light and dark) work together: the theme
  and the mode are two separate attributes on `<html>`.
- **Every page checked in all four themes**: `npm run check:contrast` (340 colour pairs, none below
  AA) and the screenshot run's axe-core audit, now looping through all four palettes at 1440 and
  390 px. The dark palettes from PB-51 passed axe on every page as they were. The one failure
  the run found was a layout problem, not a colour one: a filled document slot's status badge,
  View and Replace sat in a row that couldn't wrap and pushed a 390 px screen 4 px sideways;
  `DocumentRow`'s action row now wraps.

## Design decisions and alternatives

- **Explicit "Submit for verification" instead of "complete = in the queue".** Users in the test
  didn't know when they were finished, and an admin could open an account while the user was still
  changing it. The cost is a change to PB-11's behaviour after a rejection (submit again rather
  than any edit), agreed before building. Alternative: keep the old rule and only add the wizard.
- **Step order enforced on the server.** `OnboardingSteps::canOpen()` decides which steps can be
  opened and saved, so skipping ahead by typing a URL doesn't work. The document slots depend on
  the borrower type chosen in step 1, which is why the order matters.
- **Slots kept as history, enforced by MySQL.** A replaced document keeps its row and encrypted
  file with `replaced_at`; a generated column `current_slot` (the type while current, otherwise
  NULL) with `UNIQUE (user_id, current_slot)` means the database itself refuses two current
  documents in one slot. Alternatives: delete the old file (loses what an admin may have seen), or
  check only in PHP (two uploads at the same moment could both succeed).
- **Islands as reference tables loaded by a migration, not a seeder.** Profiles point at islands
  with a foreign key, so the list must exist everywhere (tests, CI, the demo) before any address
  can be saved. Alternatives: free text (spelling variants, no atoll check) or an address API
  (cost, network, no Maldivian coverage).
- **Legacy addresses: guess, keep, flag.** The parser fills what it safely can (it leaves an
  island name used in two atolls for the user to pick), the original text stays, and the flag
  makes the user confirm. Verified users are locked, so they are not asked; their review step shows
  the old text.
- **Filters on the server with a fixed allow-list.** Every value in the URL is checked against the
  list's own options and ignored otherwise; search text is bound as a parameter with `%` and `_`
  escaped. Alternative: filter in the browser over the whole list (doesn't scale, and PB-16 needs
  pages).
- **`return_to` checked against the route list.** A URL parameter survives reloads, new tabs and
  shared links (browser history and the Referer header don't), and it nests. Accepting only paths
  that match one of the app's own pages closes the open-redirect risk.
- **Theme saved on the user, plus a tiny head script for "system".** Saving on the user follows
  them across devices like the Shariah-only switch; the server paints a saved light or dark choice
  directly. The client hint `Sec-CH-Prefers-Color-Scheme` would let the server know the device
  setting too, but only Chromium supports it, so the script stays. It carries a CSP nonce for
  PB-44.

## Sample code

Where the wizard resumes, and which steps can be opened (`web/app/Support/OnboardingSteps.php`):

```php
public function current(): string
{
    // A verified account is locked: every step is open to read, and the wizard opens on the
    // review step.
    if ($this->user->status === 'verified') {
        return self::REVIEW;
    }

    foreach ($this->steps() as $step) {
        if (! $this->isDone($step)) {
            return $step;
        }
    }

    return self::REVIEW;
}

public function canOpen(string $step): bool
{
    $steps = $this->steps();

    return $this->has($step) && array_search($step, $steps, true) <= array_search($this->current(), $steps, true);
}
```

Only internal pages are accepted as a return URL (`web/app/Support/ReturnUrl.php`, shortened):

```php
if ($value[0] !== '/' || str_starts_with($value, '//') || str_contains($value, '\\')) {
    return null;
}

$decoded = rawurldecode($value);
if (preg_match('/[\x00-\x20\x7F]/', $value) || preg_match('/[\x00-\x1F\x7F]/', $decoded)
    || str_starts_with($decoded, '//') || str_contains($decoded, '\\')) {
    return null;
}

$parts = parse_url($value);
if ($parts === false || isset($parts['scheme']) || isset($parts['host']) || ! isset($parts['path'])) {
    return null;
}

// It must be a page of this app.
if (self::routeFor($parts['path']) === null) {
    return null;
}
```
