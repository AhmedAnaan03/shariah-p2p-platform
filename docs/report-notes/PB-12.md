# PB-12 Spike: acquire and explore the lending dataset

Sprint 1 · spike · 3 points · traces to IR 2.4.3, 1.5 · GitHub issue #12

## What was built

A documented, explored training dataset for the risk model, and the rules for using it:

- **Dataset chosen and downloaded:** LendingClub's accepted loans 2007–2018 from Kaggle
  (CC0, public domain). That is 2,260,668 loans × 151 columns, 393 MB compressed. Source,
  licence, size, period, default rate and download steps are in `risk-service/DATA.md`. The
  raw data stays in the git-ignored `risk-service/data/raw/`.
- **`ml/prepare.py`** converts the 1.6 GB CSV to a 302 MB Parquet file once, streaming it in
  batches so it fits in an 8 GB laptop's memory.
- **`ml/dataset.py`** holds every data rule in code:
  - what counts as a default;
  - which loans form the modelling population;
  - how the 15 candidate features are built;
  - the three feature sets;
  - a role, with a reason, for every one of the 151 raw columns.
- **`notebooks/PB-12-eda.ipynb`**, the exploration notebook, covers size and outcomes, the
  vintage bias, class balance, missing values, distributions, how each feature relates to
  default, overlap between features, and the recommended feature list with a "could a
  Maldivian borrower provide this?" column. It saves 8 charts for the report.
- **79 new pytest tests** (86 in the suite).

**Headline numbers.**
- Of the 1,348,099 finished loans, 19.98% defaulted.
- The modelling population is 777,399 loans with a **15.19% default rate**, an imbalance of
  5.6 : 1. It consists of individual loans whose full term had ended by the Mar 2019
  snapshot.
- Feature strength: FICO is the strongest allowed single feature (AUC 0.596). In the
  deployable set, loan-to-income (0.568) and debt-to-income (0.565) lead.

## Design decisions and alternatives

1. **LendingClub over the alternatives.** It is real peer-to-peer lending (the same model as
   our platform) with a real outcome, enough loans for PB-21's cross-validation and SMOTE,
   and fields for all four IR groups. The alternatives were rejected for these reasons:
   - Home Credit: its licence forbids reuse outside the competition.
   - German Credit: 1,000 loans, with age and sex built in.
   - Give Me Some Credit: no application fields.
   - SBA 7(a): SME loans, but no borrower capacity or history.
2. **Matured cohorts only.** If every finished loan were kept, recent years would be biased.
   For a 2017 loan to have finished by Mar 2019 it must have defaulted or been paid off
   early, so 2015–2016 60-month loans show about 36% defaults against about 25% for older
   ones (chart `PB-12-vintage-bias.png`). Keeping only loans whose full term had ended
   (`has_matured`) gives every loan the same chance to finish. *Alternative:* survival
   analysis, which uses unfinished loans properly but is beyond the scope of a
   classification model.
3. **Individual applications only**, because a request on our platform has one borrower.
   Joint applications are 5% of the file and need second-applicant fields we don't collect.
4. **Three nested feature sets** (developer's decision, recorded in `docs/decisions.md`).
   PB-21 trains all three and picks the production set from the results.

   | Set | Features | Adds | Role |
   |---|---|---|---|
   | *Deployable* | 7 | What our PB-13/PB-14 form collects as plain facts | Production candidate |
   | *Deployable + self-declared history* | 10 | `open_acc`, `delinq_2yrs`, `pub_rec` | Production candidate |
   | *Full* | 15 | FICO, credit history length, enquiries, total accounts, card utilisation | Benchmark only |

   The three self-declared answers are given by the borrower on the form. An admin checks
   them against the MMA Credit Information System report the borrower uploads. This fills
   the IR's credit-history group, which the deployable set leaves empty.

   The full set stays a benchmark because Maldivian borrowers have no FICO score, and the
   other bureau fields cannot be reliably checked from the report. It shows what a credit
   bureau would add.

   *Alternatives:*
   - Two sets with the deployable set fixed as production. This was the first version,
     replaced the same day.
   - Putting every bureau field in the self-declared set. Rejected: a borrower cannot
     self-declare a FICO score.

   *Risks for PB-21:*
   - The three answers are individually weak (AUC 0.507 to 0.513).
   - The model learned from bureau values but will receive the borrower's own answers, so
     their accuracy depends on the admin's check.
   - `pub_rec` (US public records) only approximately matches "court judgments, bankruptcy
     or debts written off".
   - PB-52 plans to pre-fill the answers from the uploaded report.
5. **Ratios, not amounts.** `loan_amnt` and `annual_inc` are in US dollars at US income levels,
   which do not carry over to MVR. `loan_to_income`, `repayment_burden` and `dti` are
   currency-free. As a bonus, loan-to-income (AUC 0.568) is stronger than the raw amount (0.506).
6. **`repayment_burden` without interest.** LendingClub's `installment` includes interest
   (and is excluded with `int_rate`). Monthly principal ÷ monthly income means the same in
   conventional and Shariah mode, so no interest rate ever enters the model.
7. **Exclusions, each with a reason.** Every column has a role:
   - **Leakage (`after_scoring`, 40 columns):** the funded amount, payments, recoveries,
     hardship, settlement, and FICO pulled during repayment. Our platform scores before
     funding, so none of these exist at that moment.
   - **LendingClub's own model output:** grade, sub-grade, interest rate, instalment. They
     are the strongest single columns (AUC 0.666) precisely *because* they are a model's
     output.
   - **Protected attributes and proxies:** ZIP code, state, and free text. The data has no
     age, sex or race columns.
   - **`verification_status`:** it runs backwards (verified 18.3% default vs not verified
     11.8%) because LendingClub verified the risky-looking applicants, and on our platform
     everyone is verified.
   - **Late bureau fields:** added in 2012 or 2015, so their gaps follow the date rather
     than the borrower.

   A test fails if any column has no role, or if a feature uses an excluded column.
8. **The full set is a conservative benchmark.** Some late bureau fields carry real signal
   (`acc_open_past_24mths`, AUC 0.580). Leaving them out means the gap PB-21 measures
   between the full set and the other two is a lower bound. This is stated in the notebook and DATA.md.
9. **Rules in a module, not only in the notebook.** Notebooks are hard to test and easy to
   run out of order. Putting the rules in `ml/dataset.py` means they are unit-tested, and
   PB-21 imports the same code, so training cannot use a different label or feature
   definition from the one explored here.
10. **Parquet cache.** Reading the CSV with pandas needs more than 8 GB of memory and takes
    minutes. The streamed conversion peaks at 2 GB, and later reads load only the columns
    needed, in seconds.

**Found during the work:** the first Parquet conversion read blank text as an empty string
`""` instead of a missing value, which hid the 5.7% of blank `emp_length` values. The fix is
`strings_can_be_null=True`, guarded by TC-12-32.

## Sample code

The maturity filter. It turns a subtle statistical bias into one testable function:

```python
# risk-service/ml/dataset.py
def has_matured(issue_dates, terms, snapshot):
    """True when the loan's full term had ended by `snapshot`."""
    issue = parse_month(issue_dates)
    months = term_months(terms)
    snapshot = pd.Timestamp(snapshot)
    issue_index = issue.dt.year * 12 + issue.dt.month
    return ((issue_index + months) <= (snapshot.year * 12 + snapshot.month)).fillna(False).astype(bool)


def modelling_population(df, snapshot):
    """Rows the model learns from, with a `default` column (0/1)."""
    label = default_label(df["loan_status"].to_numpy())
    label.index = df.index
    keep = (
        (df["application_type"] == "Individual")
        & has_matured(df["issue_d"].to_numpy(), df["term"].to_numpy(), snapshot).set_axis(df.index)
        & label.notna()
    )
    out = df.loc[keep].copy()
    out["default"] = label[keep].astype("int8")
    return out
```

Months are counted as `year * 12 + month`, so "issued Mar 2016 + 36 months" and "snapshot
Mar 2019" compare as whole numbers. A blank date or term gives NaN, and `fillna(False)`
drops the loan rather than guessing.
