# PB-03 Scaffold Flask risk-scoring service

Sprint 1 · chore · 2 points · traces to IR 2.4.3, Fig 6 · GitHub issue #3

## What was built

The skeleton of the separate Python service in `risk-service/`, which later holds the ML work
(PB-12, PB-21 to PB-24):

- A **Flask 3.1** app built by an application factory, `create_app()`.
- **`GET /health`**, returning the service name, service version and model version. There is
  no trained model yet, so `model_version` is `null`; PB-22 will fill it from the saved model.
- **JSON error responses** for every HTTP error (404, 405, …), because Laravel will read every
  response from this service as JSON.
- **`requirements.txt`** pinning the seven runtime libraries to exact versions (pandas 3.1.1,
  numpy 2.5.4, scikit-learn 1.9.1, xgboost 3.4.1, imbalanced-learn 0.14.2, shap 0.54.1,
  flask 3.1.3), plus `requirements-dev.txt` adding pytest 9.2.0.
- **Eight pytest tests**, including one that fails if any of the seven libraries is not
  pinned with `==`.

Python 3.12. Runs on port 5001: `flask --app app run --port 5001`.

## Design decisions and alternatives

1. **Application factory instead of a module-level `app = Flask(__name__)`.** A global app is
   built once at import, so every test shares its settings. The factory builds a new app per
   call, so a test can set `MODEL_VERSION` and get an app that reads it, without leaking into
   other tests. It is also the structure Flask's own tutorial uses for anything bigger than
   one file, and blueprints (one per area: health now, scoring in PB-24) plug into it.
2. **Exact pins (`==`) instead of ranges (`>=`).** The model is trained once and saved
   (PB-22). If scikit-learn, XGBoost or SHAP changed version between training and scoring,
   the saved model might not load or might explain scores differently. Exact pins make the
   report's evaluation results reproducible. Trade-off: upgrades are manual. Only the direct
   libraries are pinned, not their dependencies, which keeps the file readable; a full
   `pip freeze` lock file can be added later if a transitive update causes trouble.
3. **`model_version` is `null` rather than a made-up value.** Reporting a fake version would
   let Laravel believe a model is loaded. `null` is honest and easy to check for in PB-25.
   A blank `MODEL_VERSION=` is also treated as "no model".
4. **JSON errors.** Flask's default 404/405 pages are HTML. One `errorhandler(HTTPException)`
   turns all of them into `{"error", "message"}` JSON, which PB-24's 422 validation errors
   will follow.
5. **Port 5001.** macOS's AirPlay Receiver already listens on Flask's default port 5000.
6. **Python 3.12.** Installed on the development machine and supported by every pinned
   library. **macOS needs `brew install libomp`**: XGBoost's compiled library links to the
   OpenMP runtime and fails to import without it (found during setup and documented in the
   READMEs).

## Sample code

The application factory: one function that builds and configures the app.

```python
# risk-service/app/__init__.py
def create_app(test_config=None):
    app = Flask(__name__)

    app.config.from_mapping(
        SERVICE_NAME=SERVICE_NAME,
        SERVICE_VERSION=SERVICE_VERSION,
        MODEL_VERSION=os.environ.get("MODEL_VERSION") or None,
    )
    if test_config is not None:
        app.config.update(test_config)

    from app.health import health_bp
    app.register_blueprint(health_bp)

    @app.errorhandler(HTTPException)
    def json_error(error):
        return jsonify(error=error.name, message=error.description), error.code

    return app
```

The route reads its values from the app's config, so tests can change them:

```python
# risk-service/app/health.py
@health_bp.get("/health")
def health():
    return jsonify(
        status="ok",
        service=current_app.config["SERVICE_NAME"],
        service_version=current_app.config["SERVICE_VERSION"],
        model_version=current_app.config["MODEL_VERSION"],
    )
```
