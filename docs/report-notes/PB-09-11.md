# PB-09 – PB-11 Verification: profiles, KYC documents, admin review

Sprint 1 · stories · 5 + 2 + 3 points · traces to FR1, NFR1, IR 1.8.2, IR 1.8.3 · GitHub issues #9, #10, #11

Built as one item because the admin queue (PB-11) can only review the profiles and documents
that PB-09 and PB-10 create, and all three share one definition of "ready for review". See
`docs/decisions.md`, 12 Nov 2026.

## What was built

- **Shared UI components (groundwork).** `web/resources/js/components/` now holds the building
  blocks every page uses: Input, Select, Textarea, FileUpload, Checkbox, RadioGroup, Button,
  TextLink, Alert, Badge/StatusBadge, Card, DetailList, BulletList, Table, StepList,
  DocumentList, PageHeading, AuthLayout and PortalLayout. The PB-06–08 pages (register, sign
  in, passwords, welcome) were rebuilt on them; `Field` and `SubmitButton` were replaced.
  PortalLayout gained per-role navigation and a notice for rejected or suspended accounts.
- **Borrower profile (PB-09).** Individual or SME; phone, national ID (encrypted), address;
  for an SME also business name, registration number, sector (fixed list), years operating;
  and declared annual income or revenue. Locked once the account is verified.
- **KYC document upload (PB-09).** PDF, JPG or PNG up to 5 MB, checked by content and by
  extension. Stored encrypted on a private disk under a random name, and only readable through
  one controller action that lets the owner and administrators in.
- **Investor profile and documents (PB-10).** Phone, national ID and address, plus an ID
  document through the same upload code.
- **Suitability acknowledgement (PB-10).** Six plain-language points on capital at risk and a
  tick box. Accepting records the time once and writes an audit entry with the text version.
- **`pledge` gate (PB-10).** Only a verified investor who has accepted the acknowledgement may
  pledge. PB-19 attaches it to the pledge route; the investor portal already shows the answer.
- **Admin verification (PB-11).** A queue of complete, pending accounts (oldest first), a review
  page (profile with the decrypted ID number, documents, missing items) and an approve / reject
  form. A rejection needs a reason. Each decision updates the account and its documents, writes
  an audit entry and notifies the user (in-app and by email), all or nothing.
- **Portal checklists.** Borrower and investor home pages show the steps to verification;
  the admin home shows how many accounts are waiting.
- **156 new tests** (361 in the web suite, up from 205).

## How uploaded documents are kept private

| Layer | What it does | Where | Proved by |
|---|---|---|---|
| Private disk | Files live in `storage/app/private/kyc`, outside `public/`, with no `url` and `serve` off | `config/filesystems.php` | `test_the_disk_has_no_public_url_and_is_not_served` |
| No framework file route | Laravel 13's default `GET storage/{path}` route (signed URLs) is switched off for the `local` disk | `config/filesystems.php` | `test_no_route_serves_files_straight_from_storage`, `test_the_file_cannot_be_reached_by_its_storage_path` |
| Random names | `{user_id}/{40 random chars}.{ext}`; the extension comes from the detected type; the uploader's name is only a label | `KycDocumentStore::store` | `test_a_pdf_jpg_or_png_is_stored_on_the_private_disk` |
| Encrypted at rest | `Crypt::encryptString` (AES-256, APP_KEY) before writing; decrypted only when served | `KycDocumentStore` | `test_the_file_is_encrypted_on_disk` |
| One way in | `GET /documents/{id}`: `auth`, then `KycDocumentPolicy` (owner or admin); anyone else gets **404** | `KycDocumentController@show`, `KycDocumentPolicy` | `KycDocumentAccessTest` (owner, admin, other borrower, investors, guest, unknown id) |
| Safe headers | Detected `Content-Type`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store` | `KycDocumentController@show` | `test_the_owner_can_open_their_document` |
| Path never leaves the server | `storage_path` is `#[Hidden]`; pages get the controller URL | `KycDocument` | `test_the_documents_page_lists_own_documents_without_their_storage_path` |
| Content-checked uploads | `mimes` reads the file's bytes; `extensions` checks the name; SVG/HTML are never allowed | `StoreKycDocumentRequest` | "PHP code renamed to .pdf", "HTML with script renamed to .png" cases |

## Design decisions and alternatives

1. **Files encrypted on disk, not only hidden.** Layers 1–5 stop the web from reaching a
   file, but a copied disk or backup would still expose ID cards. Encrypting with APP_KEY
   matches how `national_id_no` is already stored. *Cost:* a file is loaded into memory to
   decrypt rather than streamed (fine at 5 MB) and takes about 1.8× the space.
   *Alternative:* rely on access control alone, which is simpler but leaves plain files on disk.
2. **404, not 403, for someone else's document.** A 403 confirms that the id exists, so
   counting through ids would reveal how many documents there are. 404 looks the same as a
   document that doesn't exist. (Portal routes keep 403: there is nothing to hide about
   whether `/admin` exists.)
3. **Content check, not trusting the name or the browser.** `mimes` uses PHP's `fileinfo` to
   read the first bytes; `extensions` checks the name. A PHP script called `id-card.pdf`
   fails the first, a real PDF called `id-card.exe` fails the second. The tests use files with
   real bytes, because Laravel's `UploadedFile::fake()` reports a type based on the name and
   would have hidden a missing content check.
4. **5 MB limit; PHP's limits set higher (10 / 12 MB).** If PHP's `upload_max_filesize` were
   exactly 5 MB, a 6 MB file would be thrown away by PHP and Laravel could only say "could not
   be uploaded". With PHP above the app's limit, Laravel sees the file and says "Files must be
   5 MB or smaller". The page also checks the size before sending, as a convenience: the server
   check is what counts, and the demo confirmed it by sending a 6 MB file past the page.
5. **One decision per account, not per document.** The admin approves or rejects the account;
   every document still pending takes the same outcome and reason. Per-document review would
   add a second form and states ("account approved, one document rejected") that no story
   needs yet. Documents rejected earlier keep their earlier decision.
6. **Decision in one transaction with a row lock; notification after commit.** The account,
   its documents and the audit entry change together or not at all (tested by making the audit
   write fail). `lockForUpdate()` makes a second admin deciding at the same moment wait and then
   see the account is no longer pending. The email is sent after the commit, so a rolled-back
   decision never tells the user anything.
7. **"Ready for review" defined once (`VerificationChecklist`).** Profile saved, plus a national
   ID, plus a business registration for an SME; a rejected document doesn't count. The borrower
   checklist, investor checklist, admin queue and approve button all use it, so they can't
   disagree. Incomplete accounts are counted, not listed, so the queue holds only work an admin
   can finish.
8. **Locked once verified; a rejected user can fix and resubmit.** Changing a profile after
   approval would make the check meaningless. After a rejection, saving the profile or
   uploading a document puts the account back to pending and clears the reason.
9. **Pledge rule as a Gate now, route in PB-19.** The acceptance criterion is about *pledging*,
   which arrives in PB-19. Building the rule now as a named gate means PB-19 only adds
   `->can('pledge')`; the tests prove the gate and a route protected by it. The gate also
   requires a verified account, which is the "only legitimate participants transact" rule
   from PB-11.
10. **The acknowledgement text lives on the server, with a version.** The page shows exactly
    `RiskAcknowledgement::POINTS`, and the audit entry records `text_version`, so it is always
    possible to say which wording an investor accepted. A test checks the facts it must state
    and that it avoids jargon and long sentences.
11. **Shared components, pages style nothing themselves.** Every page now uses the same label,
    hint and error pattern (with ARIA links between them). *Alternative:* a UI kit such as
    shadcn/ui; not used because it adds a dependency and TypeScript-style patterns to explain,
    for a handful of simple controls.

## Sample code

The one way to read a KYC file: policy first, then the decrypted bytes with safe headers.

```php
// web/app/Policies/KycDocumentPolicy.php
public function view(User $user, KycDocument $document): Response
{
    if ($user->id === $document->user_id || $user->hasRole(Role::ADMIN)) {
        return Response::allow();
    }

    // 404 rather than 403: a 403 would confirm that document 57 exists.
    return Response::denyAsNotFound();
}

// web/app/Http/Controllers/KycDocumentController.php
public function show(KycDocument $document, KycDocumentStore $store): Response
{
    Gate::authorize('view', $document);

    abort_unless($store->exists($document), 404);

    return response($store->contents($document), 200, [
        'Content-Type' => $document->mime_type,          // detected at upload, not claimed
        'Content-Disposition' => HeaderUtils::makeDisposition(
            HeaderUtils::DISPOSITION_INLINE, $document->original_name, self::asciiFallback($document->original_name),
        ),
        'X-Content-Type-Options' => 'nosniff',
        'Cache-Control' => 'private, no-store, max-age=0',
    ]);
}
```

The admin decision, all or nothing (`VerificationService`):

```php
$applicant = DB::transaction(function () use ($applicant, $admin, $approved, $reason) {
    $applicant = User::whereKey($applicant->id)->lockForUpdate()->firstOrFail();

    if (! $applicant->isPending()) {
        throw ValidationException::withMessages(['decision' => 'This account has already been decided, ...']);
    }
    // ... approval also requires VerificationChecklist::isComplete()

    $documentIds = $applicant->kycDocuments()->where('status', 'pending')->pluck('id')->all();
    $applicant->status = $approved ? 'verified' : 'rejected';
    $applicant->status_reason = $reason;
    $applicant->save();

    KycDocument::whereKey($documentIds)->update([
        'status' => $approved ? 'approved' : 'rejected',
        'reviewed_by' => $admin->id, 'reviewed_at' => now(), 'rejection_reason' => $reason,
    ]);

    AuditLog::record($approved ? 'user.verified' : 'user.rejected', $applicant, [...], $admin);

    return $applicant;
});

// After the commit: a rolled-back decision never sends an email.
$applicant->notify(new VerificationDecided($approved, $reason));
```
