# Technical decisions

Record any change from the stack justified in the IR (Section 2.4), judged against the IR's
criteria: security, clean integration, developer skill level, cost.

| Date | Decision | Alternatives considered | Reason |
|---|---|---|---|
| 26 Oct 2026 | Sprint length cut from 2 weeks to ~9 days (5 sprints, 26 Oct – 9 Dec) | Keep 2-week sprints and drop scope; fewer, longer sprints | Final deadline is 16 Dec 2026 and all work should finish a week early for review. Same scope, shorter feedback loop; mention as an adaptation in Chapter 3. |
| 27 Oct 2026 | **React integration: Inertia.js** (PB-02). Laravel controllers return React pages via `Inertia::render()`; one app, one set of routes | Separate React SPA calling a Laravel JSON API (Sanctum); Blade with React "islands" | *Security:* keeps Laravel's session login and CSRF protection, with no API tokens, CORS or cross-origin cookie setup to get wrong. *Integration:* routing, authorisation and server-side validation stay in Laravel, and validation errors reach React forms automatically. Feature tests can assert which page and props a role receives, which the role-access tests need. *Skill/time:* one codebase and one test suite instead of two, which suits a solo developer on five ~9-day sprints. *Cost:* none. Trade-off: no public API for a mobile client, which is out of scope. The Flask risk service is unaffected (Laravel calls it server-to-server). |
| 27 Oct 2026 | No Laravel starter kit; Inertia + React added by hand, in JavaScript (JSX) rather than TypeScript (PB-02) | Official Laravel React starter kit (TypeScript, shadcn/ui, built-in auth) | The starter kit ships registration, login and password reset, which are backlog items PB-06–PB-08 with their own acceptance criteria and tests. Building them in-sprint keeps every line explainable in the viva. JSX avoids a type layer the developer would also have to explain. |
| 27 Oct 2026 | MySQL 8.4 LTS installed natively with Homebrew (`mysql@8.4`), not XAMPP (PB-02) | XAMPP; MySQL in Docker | Current XAMPP bundles MariaDB, not MySQL 8, which would quietly break the IR's MySQL 8 choice. 8.4 is the long-term-support release of MySQL 8. Native avoids keeping Docker running. A test (`DatabaseConnectionTest`) fails if the server is not MySQL 8. |
| 27 Oct 2026 | Tests run on a separate MySQL database (`shariah_p2p_testing`) instead of Laravel's default in-memory SQLite (PB-02) | SQLite `:memory:` (Laravel default) | The wallet ledger relies on MySQL behaviour that SQLite ignores or differs on (row locks via `lockForUpdate`, strict foreign keys, decimal handling). Tests should prove the real engine. Cost: slightly slower tests, and CI (PB-04) needs a MySQL service container. |
